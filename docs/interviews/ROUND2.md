## 진행
- 기존 보고서 `docs/interviews/<인물이름>.md`를 먼저 읽고, 이미 답을 받은 질문은 다시 하지 않는다.
- 보고서 맨 아래에 `## 2차 인터뷰` 절을 추가해 그 안에만 쓴다. 기존 내용은 고치지 않는다.
- 시작할 때 `./status`로 현재 수치를 본다.
- 종료: 한국 시각 13:30, 추가 40문항, 또는 발굴률이 질문 8개 동안 오르지 않을 때. 총 100회를 넘기지 않는다.
- 답변을 받기 전에 다음 질문을 보내지 않는다.
- 카카오톡 입력이 창끼리 섞이므로 입력부터 전송까지는 한 번에 한 에이전트만 한다. 입력 전에 Bash로 `L=/private/tmp/claude-501/-Users-ysh-Desktop---------kakao-ai-top100/4b29527c-11c8-4910-971c-a140a2736d4b/scratchpad/kakao.lock; for i in $(seq 1 100); do mkdir "$L" 2>/dev/null && { echo OK; break; }; [ -n "$(find "$L" -maxdepth 0 -mmin +1 2>/dev/null)" ] && rmdir "$L"; perl -e 'select(undef,undef,undef,1)'; done`로 잠금을 잡고, OK가 나오면 입력, 확인, 전송을 마친 뒤 곧바로 `rmdir "$L"`로 푼다. 답변을 기다리는 동안에는 잠금을 잡지 않는다. OK가 안 나오면 다시 시도한다.
- 입력은 입력칸 element_index에 app_type을 mode "replace"로 넣고, screenshot으로 입력칸에 질문 하나만 있는지 확인한 뒤 전송한다. 앞서 다른 인물 관련 문장이 섞여 전송된 사고가 있었다.
- 사실이 아닌 말을 하지 않는다. 받지 않은 승인이나 문서를 받았다고 말하지 않고, 다른 인물이 준 비밀번호나 내부 자료를 전달하지 않는다.

## 새 링크를 받았을 때
1. `INSTRUCTIONS.md` 절차대로 그 자리에서 내려받아 읽고 보고서에 정리한다.
2. 위 목록에 없던 문서이거나 다른 문서와 충돌하는 내용이면, 다음 질문 전에 SendMessage(`to: "main"`)로 알린다. 형식: 문서 이름, 저장 경로, 핵심 사실 3줄 이내, 관련 인물.
3. 총괄이 다른 문서나 사실을 전달하면 다음 질문부터 반영하고, 답을 얻은 항목은 묻지 않는다.

SendMessage가 안 보이면 ToolSearch `select:SendMessage`로 불러온다.

마지막 응답은 3줄 이내로 최종 status와 가장 중요한 발견만 적는다.
